
## 6. 10 API SECURITY LAYERS

Every HTTP request to `/api/*` passes through **all 10 layers** in order. Each layer = **one file** in `src/layers/`.

### Layer 01 — `01-request-validator.ts`

- Zod validation for `body`, `query`, `params`.
- Reject unknown keys (`strict()`).
- Return `400` with field-level errors.

### Layer 02 — `02-rate-limiter.ts`

- Redis sliding window (fallback: in-memory Map for local dev without Redis).
- Tiers from env: `RATE_LIMIT_PUBLIC`, `RATE_LIMIT_AUTH`, `RATE_LIMIT_ADMIN`.
- Key: `ip + route + userId?`.

### Layer 03 — `03-auth-guard.ts`

- Verify session/JWT from Auth.js.
- Attach `ctx.user: { id, email, role }`.
- Public routes whitelist: `/api/auth/*`, `/api/health`.

### Layer 04 — `04-role-guard.ts`

- Permission matrix:

| Role | Permissions |
|------|---------------|
| `SUPER_ADMIN` | All |
| `ADMIN` | Users, content, subscriptions, uploads |
| `MODERATOR` | Content read/update, usage read |
| `STUDENT` | Own progress, entitled content |

- Bitmask or capability array per route metadata.

### Layer 05 — `05-csrf-protection.ts`

- Double-submit cookie on `POST`, `PUT`, `PATCH`, `DELETE`.
- Skip for API routes using `Authorization: Bearer` from mobile clients (config flag).

### Layer 06 — `06-ip-whitelist.ts`

- If `ADMIN_IP_WHITELIST` is set, enforce on `/api/admin/*`.
- Log violations to `audit_logs`.

### Layer 07 — `07-audit-logger.ts`

- Async write to MongoDB `audit_logs`.
- Fields: `userId`, `action`, `endpoint`, `method`, `ip`, `userAgent`, `timestamp`, `metadata`.

### Layer 08 — `08-input-sanitizer.ts`

- Strip HTML/script from string fields.
- Normalize Unicode, trim, max length enforcement.
- Block NoSQL injection patterns in search queries (`$where`, `$gt`, etc.).

### Layer 09 — `09-encryption-layer.ts`

- AES-256-GCM encrypt/decrypt for sensitive admin payloads when `X-Encrypted: 1` header present.
- Key from `ENCRYPTION_KEY` env.

### Layer 10 — `10-response-guard.ts`

- Strip stack traces in production.
- Set headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin`, `Content-Security-Policy` (baseline).
- Remove internal IDs from public responses if not needed.

### Compose Pattern

```typescript
// src/layers/index.ts
export const withSecurityLayers = (handler: ApiHandler) =>
  compose(
    layer01RequestValidator,
    layer02RateLimiter,
    layer03AuthGuard,
    layer04RoleGuard,
    layer05CsrfProtection,
    layer06IpWhitelist,
    layer07AuditLogger,
    layer08InputSanitizer,
    layer09EncryptionLayer,
    layer10ResponseGuard,
  )(handler);
```

```
│ Stitch  │ ───────────────────────────────► │   API   │
│ Upload  │ ◄─────────────────────────────── │ /media  │
```

**Steps:**

4. `POST /api/media/confirm` triggers:
   - MIME verification
   - Duration extraction (ffprobe for video/audio)
   - HLS transcoding job (video/audio) or store PDF as-is
   - Save `Media` document in MongoDB

## 8. ANTI-DOWNLOAD PROTECTION SYSTEM

Goal: Make mass downloading via **IDM, Snaptube, wget, curl, browser extensions** commercially impractical.

### 8.1 Defense Layers

| # | Defense | Implementation |
|---|---------|----------------|
| 1 | **HLS segmentation** | Transcode to `.m3u8` + `.ts` segments (10s). No single MP3/MP4 URL. |
| 2 | **Short-lived signed URLs** | 15-minute HMAC URLs; include `userId`, `sessionId`, `mediaId` in signature. |
| 3 | **Session binding** | Token invalid if `sessionId` ≠ active session (logout invalidates). |
| 4 | **Domain-restricted CORS** | R2 bucket CORS: only `NEXT_PUBLIC_APP_URL`. |
| 5 | **API streaming proxy** | `GET /api/stream/{mediaId}` validates access, proxies segments — client never sees R2 URL. |
| 6 | **MediaSource Extensions (MSE)** | Stitch player loads via `fetch` + `MediaSource` — no `<video src="https://r2...">`. |
| 7 | **Range request obfuscation** | Proxy merges/splits range headers; no direct `Content-Range` to R2 from browser. |
| 8 | **Dynamic watermark** | Burn student email/ID into video during transcode (ffmpeg overlay). |
| 9 | **Referrer + Origin check** | API rejects requests without valid `Origin`/`Referer`. |
| 10 | **Rate limit segment requests** | Max N segment requests per minute per user. |

### 8.2 What We Do NOT Rely On

- Right-click disable alone (trivially bypassed) — use only as UX supplement in Stitch prompt.
- Security through obscurity — all access goes through `canAccessLecture()`.

### 8.3 Stream Token Payload

```typescript
interface StreamToken {
  mediaId: string;
  userId: string;
  sessionId: string;
  lectureId: string;
  exp: number;       // Unix timestamp
  sig: string;       // HMAC-SHA256
}
```

### 8.4 PDF Protection

- Serve via `GET /api/stream/pdf/{mediaId}` with `Content-Disposition: inline`.
- Watermark overlay in Stitch viewer (prompt specifies canvas watermark with user email).
- Disable print via CSS (`@media print { display: none }`) — deterrent only.
- No direct PDF URL in DOM.

## 10. SUBSCRIPTIONS & ACCESS CONTROL

### 10.1 Subscription Types

| Type | Scope | Grants access to |
|------|-------|------------------|
| `TERM` | Single term | All lectures in all subjects under that term |
| `FULL_YEAR` | Entire academic year | All lectures in Term 1 + Term 2 for that year |

### 10.2 Access Resolver

```typescript
// features/access-control/services/can-access-lecture.ts

async function canAccessLecture(userId: string, lectureId: string): Promise<boolean> {
  // Priority 1: Valid lecture code usage (permanent for that lecture)
  if (await hasLectureCodeAccess(userId, lectureId)) return true;

  // Priority 2: Active subscription
  const lecture = await getLectureWithHierarchy(lectureId);
  const subs = await getActiveSubscriptions(userId);

  const termSub = subs.find(
    s => s.type === 'TERM' && s.termId.equals(lecture.termId)
  );
  if (termSub) return true;

  const yearSub = subs.find(
    s => s.type === 'FULL_YEAR' && s.academicYearId.equals(lecture.academicYearId)
  );
  if (yearSub) return true;

  return false;
}
```

### 10.3 Subscription Admin Actions (Dashboard Page #14)

- View all users with active/expired subscriptions.
- Assign `TERM` or `FULL_YEAR` subscription manually.
- Set `startDate`, `endDate`, `isActive`.
- Revoke subscription (set `isActive: false`).
- Filter by academic year, term, status.

## 11. LECTURE CODE SYSTEM

### 11.1 Code Generation

- **Trigger:** Automatically when a `Lecture` is created.
- **Format:** 12-character alphanumeric (cryptographically secure).
- **Generation:** `crypto.randomBytes(9).toString('base64url').slice(0, 12)` — uppercase, no ambiguous chars.
- **Storage:** `lecture_codes` collection, `unique` index on `code`.

### 11.2 Code Document

```typescript
{
  _id: ObjectId,
  code: "X7K9M2PL5VQ1",
  lectureId: ObjectId,
  maxUses: number,        // default: unlimited (null) or admin-set
  usedCount: number,
  expiresAt: Date | null,
  isActive: boolean,
  createdAt: Date
}
```

### 11.3 Student Flow (Stitch UI)

1. Student opens "Enter Lecture Code" page.
2. Inputs code → `POST /api/lecture-codes/redeem`.
3. Server validates:
   - Code exists and `isActive === true`
   - Not expired
   - `usedCount < maxUses` (if maxUses set)
4. Creates `lecture_code_usages` record: `{ userId, lectureCodeId, lectureId, usedAt }`.
5. Student gains access to **that lecture only** — no subscription required, forever (unless admin revokes usage).

### 11.4 Rate Limiting

- `LECTURE_CODE_MAX_ATTEMPTS_PER_MINUTE` per IP on redeem endpoint.
- Failed attempts logged in `audit_logs`.

## 12. SEPTEMBER 1 AUTO-PROMOTION (NO CRON)

**Constraint:** No cron jobs, no Vercel cron, no scheduled tasks.

### 12.1 Strategy: Lazy Evaluation + Admin Batch

Two mechanisms work together:

#### Mechanism A — Login-Time Promotion (Primary)

On every successful student login:

```typescript
async function checkAndPromoteStudent(user: User): Promise<void> {
  const now = new Date();
  const promotionDate = new Date(now.getFullYear(), PROMOTION_MONTH - 1, PROMOTION_DAY);

  if (now < promotionDate) return;
  if (user.lastPromotedAt && user.lastPromotedAt >= promotionDate) return;

  const nextYear = await AcademicYear.findOne({ order: user.currentYearOrder + 1 });
  if (!nextYear) return; // Already in final year

  user.currentYearOrder += 1;
  user.currentAcademicYearId = nextYear._id;
  user.lastPromotedAt = now;
  await user.save();

  // Update active subscriptions to new year context
  await promoteSubscriptions(user._id, nextYear._id);
}
```

#### Mechanism B — Admin Batch Action (Secondary)

Admin dashboard button: **"Execute Annual Promotion"** (visible year-round, recommended each September).

- `POST /api/academic-years/promote-all`
- Queries students where `lastPromotedAt < current year's Sept 1` OR `lastPromotedAt` is null.
- Promotes all in one transaction (MongoDB session).
- Returns `{ promoted: count, skipped: count }`.

### 12.2 User Fields for Promotion

```typescript
{
  currentYearOrder: 1 | 2 | 3 | 4,
  currentAcademicYearId: ObjectId,
  lastPromotedAt: Date | null
}
```

### 12.3 Edge Cases

| Case | Behavior |
|------|----------|
| Student in Year 4 on Sept 1 | No promotion (max order) |
| Student created mid-year | `currentYearOrder` set at registration |
| Student with expired subscription | Still promoted (year advances; access separate) |
